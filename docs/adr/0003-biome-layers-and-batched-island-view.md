# ADR 0003: Слои живого биома и пакетная визуализация острова

- Статус: принято
- Дата: 2026-09-06

## Контекст

Остров должен читаться как территория, а не как набор сфер, и выдерживать
больше видов и клеток без попарного поиска и без Node на каждый организм.
Канопи, органика и опыление влияют на рост и размножение, поэтому их нельзя
держать только в GDScript.

## Решение

1. Базовые поля клетки (`canopy`, `light`, `organic`, `pollination`) живут в
   `HabitatCell`. Именованные optional layers остаются для будущих законов и
   не итерируются в тике.
2. Новые виды — записи `SpeciesDefinition` с guild-параметрами
   (`canopy_contribution`, `shade_preference`, `organic_growth_factor`,
   `pollination_*`, `organic_consumption_per_hour`, `activity_min_temperature`).
   `World` не ветвится по имени вида.
3. Поиск воды и органики идёт по клеткам в радиусе, как поиск пищи по buckets.
4. `World::habitat_snapshot()` отдаёт сетку визуализатору. GDExtension копирует
   её в packed arrays; GDScript только красит рельеф и инстансы.
5. Организмы рисуются MultiMesh по виду, а не отдельными `MeshInstance3D`.

## Последствия

- Телеметрия и снимок обязаны показывать canopy/light/organic/pollination.
- Утверждение о многолетнем балансе по-прежнему требует длинных многосидовых
  прогонов; короткий survival smoke не является балансом.
- Дальнейший рост карты — chunked storage, не отказ от spatial index.

## Отклонённые варианты

- Скалярные слои только через `unordered_map`: итерация в тике ломает
  детерминизм.
- Цвета, формы и легенда в `sim_core`: это presentation.
- Полный поиск питьевой воды по всей сетке: квадратично дорожает с шириной
  острова.
